# 系统架构

RepoLens 由流式分析核心、小型本地 HTTP 服务和嵌入发布程序的浏览器界面组成。

## 数据流程

1. 验证并解析仓库和目标版本。
2. 使用 `ls-tree -z` 枚举目标版本目录树，建立当前文件索引。
3. 使用 `git log --raw --numstat -z` 和持久化 `cat-file --batch-check` 流式统计历史工作量，校验历史 Blob 大小。
4. 使用 `cat-file --batch` 逐个读取 Blob，统计代码／内容、注释、空行及语言和目录；解析静态导入及配置引用，然后对已读取文本执行有并发上限的 `blame`。
5. 归一化贡献者身份并计算各维度占比。
6. 将带版本号的分析快照写入用户缓存目录。
7. 向本地界面提供快照，或导出独立 HTML 报告。

## 大型仓库

- Git 输出采用流式解析。
- 不保留源代码和完整差异。最近提交在扫描时只保留 8 条，文件历史索引只维护当前路径，画像文件数有独立上限。
- 最近结果列表读取轻量摘要，新结果的文件树和引用图按需加载；旧结果没有摘要时兼容读取。
- `blame` 并发数可配置，并随父级上下文一起取消。
- 超大文件和二进制文件会在 `blame` 前被排除。
- 缓存键使用提交、最终生效配置、程序／算法版本、Git 版本、身份映射、Git 配置、浅克隆边界和替换引用。运行期间输入变化时拒绝保存混合结果。
- “快速”跳过 `blame`，“平衡”默认最多归属 12,000 文件，“完整”提高至 100 万；画像默认读取最多 50,000 文件，文件大小和并发限制仍生效。
- 全局只运行一个分析，最多 8 个活动任务；取消会终止子进程及队列等待。缓存使用唯一临时文件与写锁，保存失败不会标记完成。

## 安全边界

服务默认只监听本机回环地址。任务创建后，仓库路径不会返回给浏览器。分析器直接传递参数调用 Git，不使用 Shell，不检出代码，不加载项目依赖，也不会执行 Git Hook。

分析会读取配置结构和导入声明，不执行配置中的命令，也不保存配置值。完整本机配置可能包含身份别名；HTML 导出会移除完整配置、文件明细、配置键、依赖边和循环组。日期与性能校验由前后端共享的 API 完成；用户输入配置和实际生效配置分别展示。
