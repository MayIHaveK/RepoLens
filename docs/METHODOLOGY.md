# 贡献计算方法

RepoLens 展示的是版本控制历史中的可验证数据。它不会声称能够衡量开发者价值、任务难度、代码质量、辅导投入或产品影响。

## 分析维度

### 有效工作量

有效工作量根据非合并提交中的新增行和删除行计算。被忽略规则、生成文件规则、第三方代码规则、二进制规则或大小限制排除的文件不会产生工作量。源代码、测试、文档、配置和资源变更会分别统计。默认分数使用“新增行 + 删除行的一半”，原始数值仍会保留并展示。

### 当前代码所有权

当前代码所有权统计目标版本中由 `git blame --line-porcelain` 归属到各贡献者的代码行。这是面向维护工作的当前目录树视角，并不代表法律意义上的所有权。初始版本暂不区分空白行和纯注释行。

项目画像独立区分纯注释和空白；归属仍包含这些行，二者不能混为同一指标。仅对画像已经读取的 UTF-8 文本进行归属分析。达到归属上限时按路径哈希确定性选取文件，不按目录顺序截断，覆盖率以所有符合过滤和大小条件的候选文件为分母。

### 留存贡献

留存率使用同一贡献者当前拥有的代码行除以历史新增行计算，只是一种近似值。重构、压缩提交、复制代码和改写历史都可能改变归属结果，但未必能反映真实的人力投入变化。

留存率上限为 100%。留存占比分子使用未舍入的“当前归属 × 近似留存率”，展示时才舍入。使用日期筛选或停用归属时停用留存，报告会显示生效配置。

### 协作贡献

协作贡献使用可选的代码托管平台元数据，例如 Review 和 Issue 活动。Pull Request 中的代码差异已经计入有效工作量，因此不会重复计算。平台数据不可用时，RepoLens 会移除此维度，并对其余可用权重重新归一化。

## 身份归并

默认优先采用提交作者身份，而不是提交者身份。`.mailmap`、显式身份别名和 `Co-authored-by` 尾注都可能合并或拆分贡献。对于识别出的联合作者，同一提交的工作量会平均分配。

不能整除的新增／删除按作者顺序轮转分配，文件明细、提交明细和时间线使用同一分摊结果。每人的最近提交在扫描时就只保留 8 条，不累计整个历史再截断。

## 合并提交

默认不把 Merge commit 计入工作量，以免重复统计已经归属于原始提交的变更。只有目标版本可达、并且符合时间筛选条件的提交会被分析。

启用 Merge commit 后采用与第一父提交的差异，仍可能重复原始提交的工作量。日期筛选采用作者时间；YYYY-MM-DD 按 UTC 解释，开始日包含零点，结束日包含全天。大小限制同时检查历史文件变更前后 Blob，任一超过上限即跳过该文件变更。

## 可复现性

每份报告都会记录目标版本、解析后的提交、RepoLens 版本、配置指纹和生成时间。无法访问私有仓库的报告接收者不能独立证明所提供 Git 历史的真实性。因此，报告属于可复现的数据说明，而不是第三方认证。

本机结果还记录算法版本、完整生效配置和实际评分权重。无数据的维度不进入归一化分母；没有任何可用且正权重的维度时，综合占比为零。公开 HTML 移除完整配置中的别名、规则和文件关系，配置指纹仅用于识别，不足以独立恢复私有配置。

## 项目画像与关系

总物理行数 = 代码／内容行 + 纯注释行 + 空行，文件末尾换行不多计一行。UTF-8 文本经过过滤、大小和画像文件数量限制后统计；无扩展名二进制、非 UTF-8 内容与符号链接被跳过。源代码总量只汇总 source 和 test 类别，文档／配置的内容行另外展示。词法注释统计不是完整语言语法分析，字符串、模板和混合语言可能存在估算偏差。

语言和目录总量与文件明细采用相同读取范围。目录包含后代文件，不能将各层目录相加。当前路径的变更次数、新增／删除采用历史日期范围，已删除文件仅影响历史汇总，重命名前的路径历史不自动合并。

Go 导入解析为包关系；JS/TS 静态导入、CSS 引用、HTML 资源和 tsconfig 继承／references 可解析为本地文件关系。外部依赖和未解析路径单独标记，不等同于缺失文件。循环组使用强连通分量。动态表达式、路径别名、调用图与运行时配置合并尚不支持。

JSON 检查有效对象与重复键；tsconfig 支持注释和尾逗号。YAML/TOML/INI 等仅提取未缩进的键并提示重复，不宣称验证完整语法或跨环境冲突。只记录键名、依赖／脚本数量，不保存配置值，也不执行脚本。

## 缓存格式升级

0.2 本机快照使用 schemaVersion 2。旧版 schemaVersion 1 仍可加载与导出，但没有项目画像；重新分析会使用新的算法和配置缓存键生成新快照。新结果写入唯一临时文件后替换，并另存轻量摘要供最近分析列表使用。
